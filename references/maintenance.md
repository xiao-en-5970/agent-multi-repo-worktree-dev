# 维护、修复与清理

## 1. 适用范围与接管边界

用户要求检查、修复或清理已有主 checkout、分支 worktree 时使用本流程。只读检查不触发工作区初始化，不执行任何写操作。

接管现有工作区时，只在两个基座目录的共同父级生成配置并登记主 checkout。不得移动主 checkout、删除历史 worktree 或重建分支维度 worktree，不得改变已有分支、remote、依赖或项目指令。

## 2. 只读现状清单

执行 repair、prune 或清理前，先完成只读清单，不凭目录名称判断仓库或 worktree 归属：

1. 对每个相关主 checkout 执行 `git worktree list --porcelain`，记录主 checkout、各 worktree 的实际物理路径、HEAD、分支、prunable 原因及 `locked` 状态。
2. 对每个相关 checkout 和 worktree 执行 `git status --short --branch`，记录当前分支、未提交改动及未跟踪文件。
3. 读取分支与上游关系，列出相对已确认上游的全部未推送 commit；上游缺失、关系不明或证据不足时标记未决，不得判为没有未推送成果。
4. 记录用户指定分支目录的实际内容，包括 `tmp/` 交接证据。清单与目录观察不一致时停止写操作并报告差异。

此阶段不 repair、prune、fetch、删除、移动、解锁或改写文件。

## 3. 修复与元数据清理

### Repair

只有登记路径已移动或元数据路径失配时才考虑 `git worktree repair`。先核对主 checkout 与每个目标 worktree 的实际物理路径、Git 元数据和第 2 节清单；展示将修复的明确路径及命令并取得用户确认后才执行。路径不存在、归属不明、存在歧义或核对失败时停止，不猜测路径，不用 repair 掩盖其他故障。执行后重新读取 worktree 清单并报告仍存在的异常。

### Prune

`git worktree prune` 只清理已确认失效的元数据，不用于诊断或修复仍可访问的 worktree。先依据只读清单和实际路径列出精确候选及失效证据，获得用户对候选清单的确认后才执行；候选不存在、路径仍可访问、状态不明或证据冲突时停止。不得用 prune 代替故障诊断，也不得借 prune 删除有效成果。

## 4. 分支目录清理门禁

1. **明确目标。** 用户必须明确指定一个待清理分支目录。核对其物理路径、涉及仓库和 worktree 清单；不得按分支名批量匹配，不得清理主 checkout。目标不明或越出指定目录时停止。
2. **证明成果已保留。** 清理前逐仓复查 `git status --short --branch` 和上游差异，确认没有未提交改动、未跟踪文件或未推送 commit。任一项存在或无法证明不存在时，停止本次清理并列出具体文件、差异和 commit；不得以补丁、口头保证或“可能已备份”代替保留证明，不得擅自 fetch、push 或提交。
3. **处理 locked。** 目标中任一 worktree 为 `locked` 时停止本次清理，保留原状；不解锁、不强删，也不跳过锁定项继续清理其余目标。
4. **保留 `tmp/`。** 含 `tmp/` 的分支目录及其交接证据**默认保留**，不因 worktree 可移除而删除。只有用户明确要求归档并单独确认归档目的地时才创建归档；目的地不得位于待清理分支目录内，不得使用未经确认的临时目录或假定已有备份。归档后必须完成**归档校验**，逐项核对来源与归档的文件清单、相对路径、文件大小和内容校验和；校验失败或无法读取时停止并保留原始 `tmp/`。只有归档校验通过后，才可移除原始 `tmp/`。
5. **非强制移除。** 上述门禁全部通过后，展示逐仓目标路径和移除命令并取得清理确认，只使用 `git worktree remove <已确认路径>`。不使用 `--force`，不手工强删 worktree，不自动删除 Git 分支。移除失败时停止，保留现场并报告原因，不改用强制操作绕过门禁。
6. **清理后复核。** 重新执行 `git worktree list --porcelain`，检查各仓状态、目标路径及 `tmp/` 或已校验归档。确认已移除项不再登记、保留项仍存在后，才报告结果。只有分支目录实际为空时才删除该空目录；目录非空时保留并列出剩余内容，不递归强删。

## 5. 独立高风险确认

普通清理确认不涵盖以下动作。`clean`、`reset --hard`、解锁和删除 Git 分支分别是独立高风险动作；每次执行前必须单独展示精确目标、命令、影响及不可逆成果，并取得该动作的明确用户确认。任一动作的确认不得推导或替代另一动作的确认；未单独确认时不执行。强制移除 worktree 或目录不属于可确认的清理选项。

最终按阻塞与冲突、已完成项及路径、跳过项及原因、所需确认或后续动作的顺序回报。存在未决状态、保留成果或部分失败时，不得报告全部清理完成。
