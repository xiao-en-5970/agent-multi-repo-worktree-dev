# 分支交接记录

## 1. 更新时机与文件

创建分支目录后，按 `templates/branch-readme.md` 创建 `tmp/README.md`。每次提交、验证结论或环境变化后更新；阻塞出现或解除时立即更新。记录当前事实，不为呈现就绪而省略未验证工作或阻塞项。

## 2. 固定内容

交接文档依次包含：

1. 阻塞项及负责人。
2. 当前摘要、目标和共用分支。
3. 仓库矩阵：每仓基线、基线 commit、当前 commit、状态、当前阶段及证据链接。
4. 验证证据、下一步、关键决策和变更日志。

矩阵只保存每仓当前状态索引。完整命令输出、验证明细和决策材料写入 `tmp/` 下的独立附件并在对应章节链接；不在矩阵单元格中重复粘贴。记录 commit 时使用完整 SHA；验证证据包含命令、执行目录、结果和对应 commit，可链接原始输出。

## 3. 唯一状态集合

状态字段只能使用：**未开始、进行中、阻塞、完成、不适用**。不得用其他阶段或就绪措辞替代状态。

| 状态 | 使用条件 |
|---|---|
| 未开始 | 尚未开始该项工作。 |
| 进行中 | 已开始，仍有工作或验证未完成。 |
| 阻塞 | 缺少继续所需条件；必须同时填写缺失条件和负责人。 |
| 完成 | 工作范围已完成且验证通过；必须附对应 commit、命令结果或部署证据。没有证据时不得标为完成。 |
| 不适用 | 该项不属于本次范围；必须填写判定依据。 |

“当前阶段”描述正在执行的活动，不是额外状态。总体摘要沿用矩阵中的五种状态，不用未经证实成功摘要掩盖单仓阻塞或未完成验证。

## 4. 阻塞、证据与下一步

- 阻塞项置于摘要之前，逐项写明受影响仓库、缺失条件、负责人和解除条件；负责人必须是明确可处理该项的角色或用户，不能留空。
- 每项“完成”必须能在验证证据或链接附件中复核。命令失败、未执行或结果与当前 commit 不对应时，保持实际状态。
- “下一步”写明动作、执行者和等待条件；需要用户输入时列出具体问题。
- 关键决策记录选项、结论和依据。变更日志记录日期、变更内容及相关 commit 或证据链接。

初始化发生失败时，不得把部分成功写成全部分支初始化完成；停止条件禁止创建 `tmp/` 时，在最终报告中记录已验证事实和阻塞项，不另写交接文件。
