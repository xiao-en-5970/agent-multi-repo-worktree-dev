# 首次工作区初始化

## 1. 触发与只读排除

用户明确要求“初始化多仓工作区”，或当前任务需要创建、补充或维护 worktree 但没有可用配置时，执行本流程。只读排查不触发初始化，不创建目录或配置。

首次初始化不移动目录，不清理或改写已有 checkout，不执行开发分支创建、依赖安装或部署。任何 clone 均需单独确认。

## 2. 首次使用硬提醒

第一次使用且没有可用配置时，必须先向用户展示：

> 第一次使用 Agent 多仓库 Worktree 开发规范，请先指定一个目录作为 `main` 基座目录，并指定或确认一个 `WorkTree` 基座目录。`main` 目录直接存放所有项目的主分支 checkout（`main`、`master` 等）；`WorkTree` 目录存放所有分支开发目录。两个目录必须同级，后续开发 worktree 都以 `main` 中的主 checkout 为基座创建。

展示后等待用户提供或明确确认两个基座目录。任一目录未提供或未确认时停止；不得用当前目录、技能仓库目录或内置路径代替。`main` 基座目录不能直接指向某个项目仓库，两个基座目录不得相同或互相嵌套。

用户确认两个路径后，展示第 3 节的推导结构并请求确认。用户未确认推导结构前停止，不创建目录或配置。

## 3. 同级目录结构

两个基座目录必须同级。`<workspace>` 是它们的共同父目录，`mainDir` 与 `worktreeDir` 分别是用户确认路径的最后一级目录名。两个路径不在同一父目录时，要求重新选择。

```text
<workspace>/                      # 两个基座目录的共同父目录
├── .branch-worktree/
│   └── config.yaml
├── <mainDir>/                    # 用户指定的 main 基座目录
│   ├── project-a/                # 项目主分支 checkout
│   └── project-b/
└── <worktreeDir>/                # 用户指定或确认的 WorkTree 基座目录
    └── <branch-name>/            # 一次开发的分支目录
        ├── project-a/
        └── tmp/
```

配置固定为 `<workspace>/.branch-worktree/config.yaml`。工作区根目录由配置位置推导，不保存本机绝对路径。分支开发目录统一位于 `WorkTree/<branch>/`，`WorkTree/<branch>/tmp` 保存交接记录。

## 4. 配置发现与物理路径校验

按以下顺序解析配置：

1. 优先使用用户明确提供的工作区根目录或配置文件。
2. 否则从当前目录向上查找 `.branch-worktree/config.yaml`；存在多个候选时使用离当前目录最近者。
3. 未找到配置时进入第 2 节，不使用个人默认路径。解析失败时停止写操作并报告具体字段，不回退到内置项目默认值。

将两个基座目录解析为物理路径，验证它们具有共同父目录、互不嵌套，且解析后仍位于工作区内。`mainDir`、`worktreeDir` 必须是工作区内的非空单级相对目录，不得为绝对路径或包含 `..`，不得为 `.`、`.git` 或 `.branch-worktree`，且二者必须不同。

目录不存在时，先解析并校验最近现有祖先和待创建尾路径；确认结构后创建目录，再重新解析物理路径。发现路径逃逸、碰撞、基座目录自身为 Git checkout 根或 Git 不可用时停止。首版不覆盖已有路径。

在 `.branch-worktree/` 和 `config.yaml` 的任何创建或更新前，先解析工作区根目录，再分别解析并约束 `.branch-worktree/` 和 `config.yaml`。目标不存在时，解析其**最近现有祖先**并校验待创建尾路径；目标存在时解析其完整物理路径。二者的解析后的物理路径必须位于工作区内，`.branch-worktree/` 必须是目录且 `config.yaml` 必须是普通文件；元数据目录、目标文件或其现有祖先出现符号链接或文件类型碰撞时停止，不跟随链接、不修改外部目标。每次创建或更新前重新解析并复核，写入后立即复核；任一步发现逃逸或碰撞即停止全部写操作。首次使用的路径提供与结构确认门保持不变，未通过这些门前不执行上述写入。

## 5. 配置 Schema 校验

配置使用 `templates/workspace-config.yaml` 的 version 1 闭合 Schema；`version` 只能为 `1`。YAML 任意层级出现重复键、字段类型错误或未定义字段时停止，指出完整字段路径；不得让解析器静默覆盖。配置由内部生成也不是跳过校验的理由。

- `mainDir`、`worktreeDir`、`repositories` 为必填；`repositories` 允许为空列表。
- 每仓 `name`、`path` 必填且为非空字符串；`name` 在配置内唯一。
- `path` 只能是 `mainDir` 下的单级相对目录，不得为绝对路径或包含 `..`，保留值 `.`、`tmp`、`.git`、`.branch-worktree` 一律拒绝。解析符号链接后仍须位于工作区内。
- 按当前文件系统语义规范化后，仓库物理路径必须唯一；大小写或符号链接导致的碰撞也算冲突。
- `url` 可选，不得内嵌密码、token 或其他秘密凭据；发现时停止并要求改用外部认证。
- `remote`、`defaultBranch` 可选。`defaultBranch` 在用于 Git 操作前必须通过 `git check-ref-format --branch`，非法分支名停止。

**写入前停止条件：** 任一写入前校验失败时，不产生目录、配置更改、clone、fetch、worktree 操作、依赖安装、凭据读取或部署。

## 6. Remote 与默认分支选择

每仓按以下顺序且仅按此顺序选择 remote：

1. 使用显式 `remote` 配置；配置的 remote 不存在时停止。
2. 未配置且仓库只有一个 remote 时，使用该 remote。
3. 否则列出候选并询问。

不得默认使用 `origin` 或其他惯用 remote 名。首次初始化和分支初始化均使用本规则。

`defaultBranch` 未配置时，从已选 remote 的 HEAD 探测；探测失败则询问，不凭分支名猜测。未确认的 `remote` 和 `defaultBranch` 不得写入猜测值。

## 7. 接管、Clone 与执行顺序

初始化模式可为接管已有目录、新建工作区或两者混合。仓库登记来源为用户提供的清单、`main` 基座目录直接子级中经用户确认的 Git checkout，或两者组合；**不递归扫描**，不自动接管其他位置的仓库。

“有效 Git checkout”的唯一判据是：`git -C <path> rev-parse --show-toplevel` 成功，且解析后的顶层目录与 `<path>` 一致。`.git` 可以是目录或 worktree 指针文件；仅凭目录名或 `.git` 存在不算有效。

按以下顺序执行：

1. 完成第 4、5 节校验，展示目标结构、登记仓库和将执行的写操作；clone 单独确认。
2. 创建两个基座目录并重新解析物理路径，确认未逃逸或碰撞后，再创建 `.branch-worktree/` 并生成或更新配置。
3. 逐仓处理：有效 checkout 保留并登记，不切换分支、不 pull、不改 remote URL；路径已存在但不是有效 checkout 时标记冲突并跳过，不覆盖；路径不存在且有 URL 时，经确认后 clone；路径不存在且无 URL 时标记待补充，不猜测远端。
4. 按第 6 节选择 remote，读取当前分支和 worktree 列表。当前分支与 `defaultBranch` 不一致时记录“基线漂移”，不切换分支，也不把主 checkout HEAD 当作默认基线。
5. 将已确认的 `remote` 和 `defaultBranch` 写回对应仓库配置，复核目录状态，列出已登记、已 clone、已跳过、冲突和待补充项。

**幂等与停止条件：** 已有有效仓库不重复 clone；已有配置与输入一致时不重写。同一配置字段出现不同输入值时，报告语义差异并询问，不静默覆盖；未提供的字段保持原值。

任一登记仓库发生冲突、clone 失败或缺少 URL 时，最终状态为“部分完成”，不得报告“初始化完成”；已成功登记的仓库保持原状。`repositories` 为空时，最终状态为“待登记仓库”，不得进入分支开发初始化。

## 8. 最终报告

最终报告严格按以下顺序组织：

1. **阻塞项与冲突**：列出具体字段、路径或仓库及停止原因。
2. **已完成项**：列出已登记、已 clone 项及可核对路径。
3. **跳过项**：逐项说明原因，包括冲突、未确认或已有有效项。
4. **下一步与所需输入**：列出待补充 URL、待确认 remote/defaultBranch 或其他必要输入。

不得把部分成功报告为全部完成；不得用个人路径或远端假设填补缺失信息。
