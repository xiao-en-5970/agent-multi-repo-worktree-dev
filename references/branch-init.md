# 分支开发初始化

## 1. 前置条件与输入

配置必须通过 `workspace-init.md` 的校验，所有涉及仓库均已登记并具有有效主 checkout。沿用工作区规则已选择的每仓 remote；不得默认或改选 remote，也不得用主 checkout HEAD 代替远端默认基线。缺少共用分支名或涉及仓库时先询问；选择已有开发分支作为基线时，该分支必须由用户明确指定。

严格按以下顺序执行。任何写入前的停止条件触发时，不创建 `tmp/`、worktree 或分支，不静默改名，不缩小校验范围。写入后发现目标冲突时保留该路径原状，报告冲突及已验证事实。

1. **校验共用分支名。** 对共用分支名执行 `git check-ref-format --branch`，并核对每个仓库的命名规约；非法名称或规约不允许同名时停止并询问。所有仓库使用同一分支名。
2. **解析并约束分支目录。** 将 `branchDir` 解析为 `<workspace>/<worktreeDir>/<branch>/`，确认其物理路径位于 `worktreeDir` 内，且不与 `mainDir`、`.git`、`.branch-worktree` 重叠。其**父级或子级**已是另一分支工作区时停止；不得自动改名或另选目录。目录不存在时，解析最近现有祖先并校验待创建尾路径。
3. **选择并分类基线。** 明确涉及仓库及各仓基线。默认分支基线取已选 remote 的默认分支完整 commit SHA；已有开发分支必须由用户明确指定。选择非默认分支基线时，先用项目指令或 CI/CD 证据证明它不是部署环境分支；证据不足或冲突时列出候选并询问，不凭名称判断，也不设置默认部署 ref。
4. **记录主 checkout。** 记录每仓主 checkout 当前分支、当前 commit 和脏状态，不切换分支、不修改文件。当前分支与 `defaultBranch` 不一致时记录“基线漂移”；默认基线仍取已选 remote 的默认分支 commit。
5. **在任何写入前解析全部物理路径。** 对每个 `<branchDir>/<path>` 解析物理路径；目标不存在时解析**最近现有祖先**并校验待创建尾路径。全部结果必须位于 `branchDir` 内，且不得与 `tmp`、`.git`、`.branch-worktree`、其他仓库路径或已有分支工作区重叠。发现符号链接逃逸、保留路径碰撞或父子路径重叠时停止。此阶段同时读取各仓 worktree 列表，完成第 7 步所需的存在性与占用检查；不得等到部分仓库写入后才发现冲突。
6. **确认远端读取。** 对需要远端基线的仓库，逐仓展示所选 remote、fetch 命令和用途，获得用户确认后才 fetch；不 fetch 其他 remote。成功后确认目标 ref 并记录其**完整 SHA**。fetch 失败或无法确认完整 SHA 时停止；只有用户明确指定一个具体本地 commit，并确认该 commit 可能过旧后，才可改用该 commit，记录完整 SHA 和确认证据。
7. **校验通过后写入。** 先创建 `branchDir/tmp/`，再逐仓只按以下顺序处理，并把选定来源的完整 SHA 作为基线记录：
   - 目标 worktree 已存在：核对实际路径和分支一致后跳过，记录证据；不一致则报冲突，不覆盖。
   - 分支已在其他 worktree 检出：报冲突并停止该仓处理，不重复检出、不移动其他 worktree。
   - **本地分支**存在：使用其当前 commit，不重置。
   - **所选 remote** 存在唯一同名分支：使用该远端分支已确认的 commit。
   - 本地与所选 remote 均不存在同名分支：从已确认的默认基线新建。
   - 存在多个匹配或来源有歧义：停止并询问，不按日期、名称或惯例选择。
8. **保留已有历史。** 已有分支**不 reset**、**不 rebase**；不得通过删除、移动或重建分支绕过冲突，不得静默重命名分支或在不同仓库使用不同分支名。
9. **交接与回报。** 按 `handoff.md` 创建 `tmp/README.md`，填实仓库矩阵、基线 commit、当前 commit、状态和下一步。回报阻塞与冲突、成功项、跳过项、各仓 commit 和验证证据；附可核对路径。存在冲突、跳过或待确认项时不得声称全部完成。

## 2. 附加动作边界

只有工作区指令、仓库指令或用户明确要求时，才执行依赖安装等附加动作；执行前说明命令、目录和影响并取得确认。本流程不执行部署，不推断部署分支或 tag。
