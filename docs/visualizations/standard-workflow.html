AGENT MULTI-REPO WORKTREE DEVELOPMENT

边界先行。
让多仓开发，各自有序。

规范不是额外负担，而是把可预期的目录、可复核的基线、可追溯的证据变成默认路径。六个场景，看懂这套标准开发流程为何更稳。

动画开启 · 所有插画均为内嵌 SVG

无需联网 · 支持减少动画 · 可用浏览器直接打开

01

先约定边界，再开始工作

第一次使用，不猜当前目录，也不替你决定你的工作方式。

动画只强调关系：基座不动，分支各有空间。首次初始化必须先回答“主 checkout 在哪里、开发 worktree 在哪里”。

没有约定：当前目录随手改、多个需求共用一个现场，最后很难回答“这是谁改坏的”。

有了约定：主分支用于核对基线，开发分支用于实际改动，物理目录把责任边界写清楚。

02

把风险拦在第一次写入之前

规范的价值不是“出了错再修”，而是不给错误进入工作区的机会。

不是先建目录再发现问题。所有仓库的来源、目标、占用、基线都在任何 tmp/、分支或 worktree 写入前统一消解。

规范把“想当然”变成可检查的问题：这个 remote 是谁选的？默认分支指向哪个完整 SHA？本地与远端同名分支是同一提交，还是已经分叉？

03

隔离性，让每个需求拥有自己的现场

并行开发不等于互相干扰。每个分支目录都是一个完整、可独立验证的工作单元。

需求之间不再有“你覆盖我”的隐性竞争。不同分支的代码、依赖、日志和验证现场都能独立检查。

改动不串线

在 A 的 worktree 修改，不会意外进入 B 的分支。

实验不污染基座

主 checkout 不切换、不重置，保留可核对的干净参照。

冲突提前暴露

路径嵌套、重复检出、来源分歧在写入前成为明确阻塞。

04

部署不看习惯，看每个项目的真实实现

“别的项目这样发布”不能成为这个项目的部署依据。

CI 文件只是入口，不是结论。必须沿 include、可复用 workflow、部署脚本和环境校验，读到目标 commit 的真实控制逻辑。

不通用：固定 `test`、`uat` 分支或 tag 格式，套到所有仓库。

真正通用：规则可以不同，但每个结论都必须由该仓当前 CI/CD 证据支持。

05

让下一位接手者，从事实开始

交接不是“我差不多做完了”，而是把状态、证据、阻塞和下一步放在同一个入口。

矩阵是状态索引，详细证据放到 tmp/ 附件并链接。即使证据尚缺，也要链接到明确记录缺失命令、负责人和所需结果的待补记录。

可交接性 = 减少重新理解成本。下一个 agent 或同事不必重走整条排查链，就能知道哪些已验证、哪些不能做、下一步由谁完成。

06

规范不是限制，而是把自由度放在安全边界内

每个项目仍然可以不同；不同的实现，不必牺牲相同的安全与协作标准。

规范性

约定目录、分支、基线和证据格式，让每一步有明确输入与停止条件。

隔离性

需求间不共享修改现场，主分支不被开发动作意外污染。

可验证性

结论对应具体提交、命令、路径和 CI 证据，不靠“应该如此”。

可交接性

结构化状态与链接化证据，减少跨 agent、跨同事的理解成本。

可复用性

不绑定个人路径、组织仓库或部署惯例，任何团队都能从自身事实出发。

可审查性

把风险转化为可观察的边界，让评审聚焦真实差异而非猜测现场。

一句话：用统一的边界管理多仓复杂性，用各自的证据决定项目差异。
